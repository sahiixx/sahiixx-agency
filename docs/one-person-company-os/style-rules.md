# Style Rules

## Words I never use
- "Game-changer", "revolutionary", "unprecedented".
- "In today's fast-paced world".
- "Leverage", "synergy", "utilize" (just say "use").
- "Delve", "embark", "navigate the landscape".

## Formatting rules
- Short sentences. If it can be split, split it.
- Active verbs. "OPA dispatches" not "OPA can dispatch."
- One idea per paragraph.
- Bullets for scannable lists, not for hiding from real prose.
- Commands and code paths are exact. No hand-wavy "just run it."

## Length rules
- README updates: under 400 words unless it's a spec.
- CLI help text: under 120 chars per line.
- Process files: 8 steps max.
- Newsletter/X posts: follow the separate process files.

## Tone rules
- Mentor, not teacher.
- Honest, not harsh.
- Specific, not vague.
- Confident, not arrogant.

## The final check
Before anything goes live, ask: "Could this have been written by anyone?" If yes, rewrite until the answer is no.
